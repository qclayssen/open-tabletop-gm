@app.route("/maps/<name>/grid", methods=["POST"])
def map_grid(name):
    """Body: {cell_px, offset_x, offset_y}. Rewrites the map file's `grid` key.

    ── NOT WIRED. This block is complete and tested, but it is NOT in
    display/gm-display-app.py and this PR does not add it there.

    Why: CAT-8 was told display/gm-display-app.py is owned by another lane, and
    PR #214 (feat/multi-display-four-windows) has it open with uncommitted local
    edits. Adding a route to that file guarantees a conflict for a change that
    does not need it.

    What IS in this PR: `mapeditor.apply_alignment` (the whole rule, as a pure
    function), `mapeditor.alignment`, `mapeditor.alignment_fits`, the editor
    page and its JavaScript, and 30 tests that exercise the rule without a route.
    All of the acceptance criteria except "Save posts to a route" are met and
    tested. The route below is the one remaining piece and it is about twenty
    lines.

    To wire it: paste this block directly after `map_features` in
    display/gm-display-app.py, and confirm the editor posts to `/grid`, which it
    does. `_token_ok`, `_mapeditor`, `find`, `write` and `editor_state` are all
    already in that file's namespace from the routes above.

    The two ways this can lose work, and what each costs:

    * **Tokens.** `_token_ok()` is not a gate in the way people assume -- index()
      mints the token into every page, so any browser on the LAN has it. That is
      fine for terrain painting, which is a GM's own local tool, and it is the
      same posture this route takes. It is *not* fine for anything a player could
      be talked into clicking, which is why pins have no write route at all
      (see the pin block below). A grid alignment is not that: nobody is misled
      by a GM moving a grid by four pixels.

    * **The save gate.** `/features` asks for `confirm` when a map already has
      terrain, because painting over an hour of work needs to be deliberate.
      Alignment does NOT, and that asymmetry is deliberate rather than an
      oversight: `apply_alignment` assigns two keys and cannot touch `features`,
      so there is nothing to overwrite. Adding a confirm here would teach the GM
      a prompt for a button that cannot lose anything, and prompts that always
      appear are prompts people stop reading. The `.bak` still happens, because
      `mapeditor.write` does it unconditionally.

    On refusal: a bad number, a pitch that does not fit the board, or a map with
    no artwork to align against all return 400 with `apply_alignment`'s own
    message. The editor's own readout predicts both of those before the GM
    presses the button, so this route is the second line and not the first.
    """

    if not _token_ok():
        return "Forbidden", 403
    path = _mapeditor.find(name)
    if path is None:
        return _map_not_found(name)
    before = path.read_text(encoding="utf-8")
    try:
        spec = json.loads(before)
    except ValueError as e:
        return jsonify({"error": f"{path.name} could not be read: {e}"}), 400
    if not isinstance(spec, dict):
        return jsonify({"error": f"{path.name} could not be read: not a map object"}), 400

    body = request.get_json(silent=True) or {}
    try:
        merged = _mapeditor.apply_alignment(spec, body)
    except ValueError as e:
        return jsonify({"error": str(e)}), 400
    try:
        bak = _mapeditor.write(path, merged)
    except OSError as e:
        return jsonify({"error": f"{path.name} could not be written: {e}"}), 500
    compiled = json.loads(path.read_text(encoding="utf-8"))
    return jsonify({
        "ok": True,
        "slug": path.stem,
        "alignment": _mapeditor.alignment(compiled),
        "backup": bak.name if bak != path else "",
        # The full editor state, so the page cannot drift from the file. Same
        # shape /features returns and for the same reason.
        "state": _mapeditor.editor_state(compiled, path.stem),
    })
